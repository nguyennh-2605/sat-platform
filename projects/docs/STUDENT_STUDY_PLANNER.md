# Student Study Planner

Student Overview retains its Productivity layout, summary cards, Tasks card, Progress, Practice Picks, calendar and recent results. Open planner replaces New task on the Tasks card and carries Today/Tomorrow/the selected date, or This week. The planner route is Student-only.

Overview Tasks and all three planner views display only events with a learner-owned plannedDate. Teacher assignments, announcements and other accessible coursework remain available to link when the student creates an event; source deadlines never add events automatically. The Overview list sorts by planned day/start time, displays only title and time range (or All day), and shares event content, completion styling, the details/edit dialog and mutation handling with the calendar. Overview rows use a neutral background with the title on the left and the time aligned right on the same row; calendar events retain their saved colors. Titles capitalize only the initial letter, including legacy displayed titles; personal titles are also normalized on save. Completed events have a pointer-transparent horizontal line across the full box. It has no reorder handles, source badges or separate personal-task editor. A shared 24px circular Checkbox before each title completes/reopens the task directly without opening details; it is a sibling of the details button, with keyboard support, in-flight protection and disabled source-driven completion. The full-row completion strike includes the circle. Completed events stay visible on their planned day. Today counts, weekly completion and the Overview mini-calendar markers use only learner-planned events.

## Calendar interaction

`/dashboard/study-planner` has Day, Week and Month views. Day and Week display a full-height 24-hour grid with 30-minute selection slots, starting at 00:00. The entire planner page owns vertical scrolling; the calendar and All day strip expand with content rather than keeping independent vertical scroll areas. Selecting a slot opens the shared event modal with its date/start time and a default one-hour duration (clipped to the end of the day). The centered toolbar groups date navigation, Today, view controls and Add event. Month cells open an all-day event draft; date numbers open Day. On mobile, Week and Month retain horizontal scrolling inside the calendar rather than overflowing the page. Slot Arrow keys navigate times/days and bring off-screen slots into the page viewport; Enter opens the modal.

Clicking an existing event opens a read-only details popup with its title, date/time, notes and resolved color. Its actions are Mark complete/Reopen, Edit and Delete according to the task's capabilities; coursework can open its owning feature. Edit switches to the edit modal and focuses the first editable control. Completion and deletion are available from details rather than the edit form. Clicking an empty slot still opens creation directly. Hour labels and weekday headings use 14px neutral text with stronger weight/contrast.

The creation/edit modal accepts a title, notes, date and either a time range or All-day event. Time entry uses explicit 24-hour HH:mm; 24:00 means the end of the selected day. Existing unscheduled personal/coursework tasks can be linked in the creation modal; there is no Unscheduled panel. Coursework title/deadline/completion ownership stays with the source feature. Only personal tasks and announcements can be marked complete manually. Completed events stay on the calendar with a check and a horizontal strike across the full event box by default; Show completed can hide them explicitly.

Events use the shared rectangular Button calendar variant, align to slot boundaries, and have no curved leading border. The modal offers Blue, Violet, Teal, Amber and Automatic. Automatic uses Personal blue, Test/Quiz/Assignment violet, Vocabulary teal and Announcement amber; choosing a color never changes the task type. Titles use semibold neutral foreground and times use a lighter neutral subtle color, with readable dark-mode equivalents. Hour boundaries use stronger borders than half-hour lines. Tokens remain scoped to calendar content; the global primary and shell stay neutral. Overlapping timed events use separate lanes; adjacent events occupy the full column. Legacy day-only plans appear in All day. Source deadlines do not appear as events, including on a different day from the study plan. The timezone instruction under the grid is omitted.

Dragging moves a learner's event and preserves its duration and color. Undo restores its prior day and times. A keyboard/mobile alternative is to open the event and edit its fields. Mutations are serialized; failed moves roll back and failed saves keep the draft. Outside, Close/Cancel and Escape all share the same close handler, which confirms unsaved changes and blocks dismissal only while saving. Per the user's request, event dialogs use the shared Modal's viewport alignment so they center on the full screen; Overview Score Goal and SAT-date dialogs also opt into viewport alignment; other dashboard dialogs keep content alignment. SatDateDialog exposes an optional alignment prop so its other callers retain the default content alignment. Date, view and completed visibility are URL-backed so reload keeps the calendar context.

After an event is moved, the Undo status bar sticks near the bottom of the planner viewport so it remains reachable while the full-height calendar is scrolled.

## Data and authorization

- `UserTodoState` stores learner-owned `plannedDate` (YYYY-MM-DD), `plannedStartMinutes` and `plannedEndMinutes`. Minutes refer to the platform study timezone (Asia/Ho_Chi_Minh), not UTC offsets or a source deadline. Both minute fields are null for all-day plans; legacy rows stay null without assigning fabricated times.
- `PUT /api/student/tasks/schedule` accepts `{ itemKey, plannedDate, plannedStartMinutes?, plannedEndMinutes? }` after verifying student role and access to the source task. Date-only callers preserve an existing event's times. Explicit null times make a plan all-day; null plannedDate clears the entire range.
- A timed plan needs an ISO study day in 2000–2100 and paired integer minutes with start >= 0, end <= 1440 and a duration of at least 15 minutes. A database CHECK also enforces the paired range. Events stay within one study day.
- Existing `POST /api/student/tasks` and `PATCH /api/student/tasks/:id` accept the same optional plan fields. Personal event creation/editing writes the task and plan in a single transaction, so an unsuccessful schedule cannot leave a half-created event. Deletion removes the owned task and plan together.
- `UserTodoState.calendarColor` is nullable and accepts only BLUE/VIOLET/TEAL/AMBER, with a database CHECK. Null uses the automatic type palette. Create/edit/schedule accept optional calendarColor; omitted colors preserve stored values and explicit null resets Automatic. Color-only edits retain date/times, and source-task colors remain learner-owned.
- Assessed coursework completion remains source-driven; planning never changes its deadline, submission or activity records. Existing unified-task limits (120 accessible items) remain in place. There are no reminder jobs or external calendar integrations.

## Development and deployment

Schema-first migrations `20261007160000_student_study_planner`, `20261013120000_student_calendar_times` and `20261013140000_student_calendar_color` add nullable planning/color fields and constraints. They do not delete records or backfill old plans with artificial times/colors. They were applied explicitly to verified development `localhost/sat_db`; unrelated pending migrations and production were not touched. Prisma Client was regenerated and the local API watcher restarted.

For deployment, inspect pending migrations, apply with `npm run db:migrate:deploy` from server, regenerate Prisma Client and restart the API. Do not reset the database or use accept-data-loss commands.
